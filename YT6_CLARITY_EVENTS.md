# YT6 — Clarity Events

This document defines the types of clarity events that occur within the YT6 clarity-system.

## Event Type 1 — Intention Event
Triggered when:
- user direction changes
- new goal appears
- new clarity anchor is needed

System Response:
- update intention clarity
- stabilise direction

## Event Type 2 — Action Event
Triggered when:
- next correct move is required
- operator command is issued
- clarity spine advances

System Response:
- provide deterministic action
- maintain operator-grade clarity

## Event Type 3 — Reflection Event
Triggered when:
- clarity changes
- new truth emerges
- system state updates

System Response:
- reflect change
- stabilise clarity evolution

## Event Type 4 — Symbol Event
Triggered when:
- Base44 symbol is referenced
- symbol meaning is tested
- symbol stability is required

System Response:
- preserve meaning
- prevent drift

## Event Type 5 — Lifebox Event
Triggered when:
- daily clarity is affected
- footprint moment occurs
- emotional pressure appears

System Response:
- stabilise clarity
- maintain non-emotional behaviour

## Event Type 6 — Drift Event
Triggered when:
- ambiguity appears
- pressure increases
- long-form sequence stresses clarity

System Response:
- activate anti-drift rules
- maintain stability

These events define the internal behaviour of YT6.
